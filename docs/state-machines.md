# 状态转换基线

| 对象 | 合法路径 | 拒绝路径 |
| --- | --- | --- |
| 订单 | 待派单→待接单→待服务→服务中→待确认→已完成 | 跳级、无权确认、服务后普通改派 |
| 开始前取消 | 待派单/待接单/待服务→已取消 | 服务中取消；改走异常协调 |
| 异常处理 | 服务中→中断→管理员提出异常费用→有权用户同意→异常结案；正常完成后可另开事后争议 | 超时自动完成、管理员冒充用户确认 |
| 派单 | 有效派单→接受或拒绝；改派保留旧记录、新人重新接单 | 同单双活跃派单、人员时段重叠 |
| 结算 | 待结算→模拟处理中→成功/失败/终止；或待结算→线下登记成功 | 未终止旧交易切换方式、晚到状态覆盖有效结算 |
| 通知/待办 | 订单事件→outbox→站内消息→已读；高优先级待办由当前订单/人员状态计算 | 将已读当作业务完成 |

所有转移由命令接口与服务端当前权限、状态、版本共同约束，不提供任意状态写接口。

补服务按“中断→独立计划→重新派单/履约→有权用户确认”实现，原履约记录保留；隔离 MySQL 已核对同一订单的中断与补服务两条独立履约记录。中断后费用拒绝、重新提案、同意与异常结案已实测；正常完成后争议另建记录，不覆盖原完成事实或已生效结算。真实退款与结算后重写费用均不在首期范围。
